Below is the full lab terminal setup.

**Safety First**
Before running the follower: clear the arena, keep an operator next to the TurtleBot, keep `Ctrl+C` ready, and keep a physical stop option available.

**Terminal A: Robot Bringup**
Skip this if robot bringup is already running.

```bash
cd /workspace/mii-amr

source /opt/ros/humble/setup.bash
source /opt/tb3_src_ws/install/setup.bash

export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0
export TURTLEBOT3_MODEL=burger
export LDS_MODEL=LDS-01

ros2 launch turtlebot3_bringup robot.launch.py
```

**Terminal B: Nav2 Localization With Saved Map**
Use the map you generated:

```bash
cd /workspace/mii-amr

source /opt/ros/humble/setup.bash
source /opt/tb3_src_ws/install/setup.bash

export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0
export TURTLEBOT3_MODEL=burger
export LDS_MODEL=LDS-01

ros2 launch turtlebot3_navigation2 navigation2.launch.py \
  use_sim_time:=False \
  map:=$PWD/maps/aufgabe03/arena_1p898x3p9_auto.yaml
```

For the manual follower/debug workflow in RViz:
1. Use **2D Pose Estimate**.
2. Align the robot pose with the real robot.
3. Confirm `/scan` overlaps the map walls.
4. Do **not** send a Nav2 Goal while using your custom follower.

For the two-stage coordinator below, RViz 2D Pose Estimate is not required in
the normal global-localization mode. Keep RViz open if you want to inspect
`/scan`, particles, and the map alignment.

**Terminal S: Safety Stop**
Keep this ready. Run it immediately if needed.

```bash
source /opt/ros/humble/setup.bash
source /opt/tb3_src_ws/install/setup.bash

export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0

ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.0}, angular: {z: 0.0}}"
```

**Terminal C: Pre-Run Checks**
Run these before motion:

```bash
cd /workspace/mii-amr

source /opt/ros/humble/setup.bash
source /opt/tb3_src_ws/install/setup.bash

export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0
export TURTLEBOT3_MODEL=burger
export LDS_MODEL=LDS-01

ros2 topic echo --once /scan
ros2 service list | grep reinitialize_global_localization
ros2 action list | grep navigate_to_pose
```

Check that no active Nav2 controller is competing on `/cmd_vel`:

```bash
ros2 topic info /cmd_vel --verbose
```

If you see Nav2 as a publisher, make sure there is no active Nav2 goal. Your script will publish `/cmd_vel` itself.

```bash
cd /workspace/mii-amr

export ROS_DOMAIN_ID=30

```

Expected staging target from the current CSV:

```text
waypoint 0: x=0.005, y=-0.015
computed staging yaw: 0.0 deg
```

**Terminal D: Run Two-Stage Waypoint Following**
Only run after bringup, Nav2, and the pre-run checks pass.

```bash
python3 scripts/aufgabe03/two_stage_waypoint_run.py \
  --waypoints results/aufgabe03/aufgabe03_waypoints.csv \
  --run-id waypoint_two_stage_001
```

When prompted, type:

```text
RUN
```

The coordinator will:

```text
global AMCL localization -> bounded scan-safe spin -> Nav2 to waypoint 0 -> custom follower
```

If global localization is ambiguous in the arena, use known-start mode instead:

```bash
python3 scripts/aufgabe03/two_stage_waypoint_run.py \
  --waypoints results/aufgabe03/aufgabe03_waypoints.csv \
  --run-id waypoint_two_stage_known_001 \
  --localization-mode known-start \
  --initial-pose-x 0.0 \
  --initial-pose-y 0.0 \
  --initial-pose-yaw-deg 0.0
```

**After The Run**
Check the coordinator log:

```bash
tail -n 3 results/aufgabe03/aufgabe03_two_stage_runs.csv
```

Also check the follower log:

```bash
tail -n 3 results/aufgabe03/aufgabe03_waypoint_follow_runs.csv
```

**Manual Follower Fallback**
Only run this after RViz alignment and checks pass:

```bash
python3 scripts/aufgabe03/follow_planned_waypoints.py \
  --waypoints results/aufgabe03/aufgabe03_waypoints.csv \
  --run-id waypoint_follow_001
```

The important fields are:

```text
status
reached_count
blocked_waypoint_index
timeout_waypoint_index
base_frame_used
final_x/final_y/final_yaw_deg
min_scan_range_m
p05_scan_range_m
amcl_var_x/amcl_var_y/amcl_var_yaw
```
